    Define ALL tables needed across all phases. This is the complete schema — future phases add data, not tables. Use `sqliteTable` from `drizzle-orm/sqlite-core`. Follow snake_case for DB columns, camelCase for TS properties.

    Tables to create:

    1. `transactions` — core transaction records from CSV import
       - `id` INTEGER PRIMARY KEY AUTOINCREMENT
       - `order_id` TEXT NOT NULL — original order ID from exchange
       - `exchange` TEXT NOT NULL DEFAULT 'bitget'
       - `source_type` TEXT NOT NULL — which CSV format it came from (spot_tx, futures_tx, spot_order, futures_order, earn)
       - `canonical_type` TEXT NOT NULL — normalized type (buy, sell, fee, earn_deposit, earn_interest, futures_open, futures_close, etc.)
       - `symbol` TEXT NOT NULL — coin symbol (BTC, ETH, etc.)
       - `side` TEXT — buy/sell/null
       - `amount` TEXT NOT NULL — monetary, Decimal.js
       - `price` TEXT — monetary, nullable (EUR price filled by enrichment)
       - `fee` TEXT NOT NULL DEFAULT '0' — monetary
       - `total_value` TEXT — monetary, nullable
       - `traded_at` TEXT NOT NULL — ISO 8601 timestamp string
       - `tax_year` INTEGER NOT NULL — extracted year for filtering
       - `source_file` TEXT — original filename
       - `raw_row` TEXT — JSON blob of original CSV row for audit
       - `checksum` TEXT NOT NULL — SHA-256 of normalized row for dedup
       - `imported_at` TEXT NOT NULL — ISO 8601 timestamp
       - UNIQUE constraint on (order_id, exchange, checksum) for dedup

    2. `price_cache` — cached EUR prices for transactions
       - `id` INTEGER PRIMARY KEY AUTOINCREMENT
       - `symbol` TEXT NOT NULL
       - `timestamp` TEXT NOT NULL — ISO 8601
       - `eur_price` TEXT NOT NULL — monetary
       - `source` TEXT NOT NULL — 'bitget-direct', 'bitget-usdt', 'coingecko'

    3. `fifo_lots` — FIFO lot tracking for cost basis
       - `id` INTEGER PRIMARY KEY AUTOINCREMENT
       - `symbol` TEXT NOT NULL
       - `original_amount` TEXT NOT NULL — monetary
       - `remaining_amount` TEXT NOT NULL — monetary
       - `cost_basis_eur` TEXT NOT NULL — monetary (total EUR cost of this lot)
       - `cost_per_unit_eur` TEXT NOT NULL — monetary
       - `fee_eur` TEXT NOT NULL DEFAULT '0' — monetary
       - `acquired_at` TEXT NOT NULL — ISO 8601
       - `transaction_id` INTEGER NOT NULL REFERENCES transactions(id)
       - `tax_year` INTEGER NOT NULL

    **packages/backend/src/db/client.ts:**
    ```typescript
    import Database from 'better-sqlite3'
    import { drizzle } from 'drizzle-orm/better-sqlite3'
    import * as schema from './schema.js'

    const sqlite = new Database('cryptax.db')
    // WAL mode — set once at startup for concurrent read performance
    sqlite.pragma('journal_mode = WAL')
    // Foreign keys — enforce referential integrity
    sqlite.pragma('foreign_keys = ON')

    export const db = drizzle(sqlite, { schema })
    export { sqlite }
    ```

  <action>
    Run `npx drizzle-kit generate` to produce the initial migration SQL.

    After generation, open the SQL file(s) in `packages/backend/drizzle/` and manually edit EVERY `CREATE TABLE` statement to append `STRICT` at the end:
    ```sql
    CREATE TABLE `transactions` (
      ...
    ) STRICT;
    ```

    This is critical — per research, Drizzle ORM does not have a first-class STRICT option. The manual edit is a one-time step per table, tracked in version control.

    Then run `npx drizzle-kit migrate` to apply the migration and create the database.

    Verify the tables exist and STRICT mode is active by querying:
    ```sql
    SELECT sql FROM sqlite_master WHERE type='table';
    ```
    Each table's CREATE statement should end with `STRICT`.

    Also verify WAL mode:
    ```sql
    PRAGMA journal_mode;
    ```
    Should return `wal`.

    Add `*.db`, `*.db-wal`, `*.db-shm` to .gitignore if not already present.
  </action>

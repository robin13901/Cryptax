# Plan 02-07: Format Detector + Normalizer (TDD)

## Objective

Build the format detection, canonical type mapping, normalization, and checksum modules that tie all 5 parsers together into a unified pipeline. This is the orchestration layer between raw CSV text and database-ready transaction objects.

Purpose: The detector identifies which of 5 formats a CSV file is (with delimiter detection first). The normalizer converts parser-specific output into the unified `transactions` table shape. The type map translates all 22 raw Bitget type strings to canonical types. These modules connect the parsers (02-02 through 02-06) to the insert layer (02-08).

Output: detect-format, parse-csv, type-map, normalize, checksum modules — all with tests.

    **detect-format.ts:**
    1. Export `detectDelimiter(headerLine: string): ';' | ','` — count semicolons vs commas, return whichever has more. This MUST run before format detection.
    2. Export `detectFormat(rawText: string): SourceType` — strip BOM, get first line, split by detected delimiter, normalize columns to lowercase, then match by unique column signatures:
       - `'interest coin'` AND `'reference'` -> `'earn'`
       - `'netprofits'` AND `'realized p/l'` -> `'futures_order'`
       - `'trading pair'` AND `'base asset'` -> `'spot_order'`
       - `'futures'` AND `'wallet balance'` -> `'futures_tx'`
       - `'available'` -> `'spot_tx'`
       - Otherwise throw `Error('Unknown CSV format. Headers: ...')`
    3. Order of checks matters — most specific first (earn, futures_order) to least specific (spot_tx).

    **detect-format.test.ts:**
    - Test detectDelimiter with semicolon-heavy line -> ';'
    - Test detectDelimiter with comma-heavy line -> ','
    - Test detectFormat with each of the 5 actual header lines from RESEARCH.md
    - Test detectFormat with BOM-prefixed header -> still detects correctly
    - Test detectFormat with unknown header -> throws Error
    - Test that 2024 spot (semicolon) and 2025 spot (comma) BOTH return 'spot_tx'

    **parse-csv.ts:**
    1. Export `parseRawCSV(fileText: string): { format: SourceType; delimiter: ';' | ','; rows: Record<string, string>[] }` using csv-parse/sync:
       ```typescript
       import { parse } from 'csv-parse/sync';
       ```
    2. Strip BOM, detect delimiter from first line, detect format, then parse with:
       `{ bom: true, delimiter, columns: true, skip_empty_lines: true, trim: true, relax_column_count: true }`
    3. Return format, delimiter, and parsed rows array.

    **parse-csv.test.ts:**
    - Test with a small synthetic semicolon CSV (3 rows) -> returns 'spot_tx', ';', 3 rows
    - Test with a small synthetic comma CSV -> returns correct format and rows
    - Test BOM handling -> BOM stripped, columns correct
    - Test trim -> tab-prefixed values have tabs stripped
    - Test empty lines skipped

    **checksum.ts:**
    1. Export `computeChecksum(row: Record<string, string>): string`
    2. Use `createHash('sha256')` from `node:crypto`
    3. Hash `JSON.stringify(row)` (deterministic for same column order since csv-parse preserves column order)
    4. Return hex digest

    **checksum.test.ts:**
    - Same row content -> same checksum
    - Different row content -> different checksum
    - Returns 64-char hex string

    **type-map.test.ts:**
    - Test every one of the 22 mappings explicitly
    - Test unknown type string -> returns 'unknown'
    - Test case-sensitive matching (Bitget types are case-sensitive)
    - Test the Bitget typo: 'risk_captital_user_transfer' -> 'transfer_in'

    **normalize.ts:**
    1. Export `normalizeRows(parsedRows: ParsedSpotTx[] | ParsedFuturesTx[] | ParsedSpotOrder[] | ParsedFuturesOrder[] | ParsedEarn[], format: SourceType, filename: string): NormalizedTransaction[]`

       Actually, use a cleaner approach with a discriminated union or separate normalize functions per format. The recommended approach:

       Export `normalizeToTransaction(row: any, format: SourceType, filename: string, rawCsvRow: Record<string, string>): typeof transactions.$inferInsert`

       This function takes ONE parsed row (from any parser) and returns a transaction insert object matching the Drizzle schema shape:
       ```typescript
       {
         orderId: string | null,
         exchange: 'bitget',
         sourceType: format,
         canonicalType: mapCanonicalType(format, row.rawType),
         symbol: /* derived per format */,
         side: /* derived from canonicalType */,
         amount: /* from row, use '0' if empty */,
         price: /* from row or '0' if format has no price */,
         fee: /* from row or '0' */,
         totalValue: /* from row or '0' */,
         tradedAt: /* from row */,
         taxYear: parseInt(tradedAt.substring(0, 4), 10),
         sourceFile: filename,
         rawRow: JSON.stringify(rawCsvRow),
         checksum: computeChecksum(rawCsvRow),
         importedAt: new Date().toISOString(),
       }
       ```

    2. Per-format symbol derivation:
       - spot_tx: `row.symbol` (Coin column)
       - futures_tx: `row.futures` (Futures column, e.g., 'POPCATUSDT')
       - earn: `row.interestCoin` (Interest coin column)
       - spot_order: `row.symbol` (already derived as 'BASE/QUOTE')
       - futures_order: `row.futures` (Futures column)

    3. Per-format side derivation from canonicalType:
       - 'buy' | 'earn_interest' | 'earn_deposit' | 'transfer_in' -> 'buy'
       - 'sell' | 'transfer_out' -> 'sell'
       - futures types: derive from name (open_long/close_short -> 'buy', open_short/close_long -> 'sell')
       - 'unknown' | 'futures_funding' | 'fee' -> null

    4. CRITICAL: `price` and `totalValue` are NOT NULL in the DB schema. For formats without price (spot_tx, futures_tx, earn), use `'0'`. Same for totalValue — use `'0'` if not available.

    5. Tax year extraction: `parseInt(tradedAt.substring(0, 4), 10)` — simple and reliable for the date format used ('2024-12-31 23:17:21').

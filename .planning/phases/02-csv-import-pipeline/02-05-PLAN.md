# Plan 02-05: Futures Order History Parser (TDD)

## Objective

Build a parser for Bitget futures order history CSVs using TDD. This format has 15 columns including Realized P/L, NetProfits, and direction-based typing similar to spot orders.

Purpose: Futures order history provides detailed order-level data with P/L information needed for futures tax calculations in Phase 4. It has the most columns of any format (15).

Output: `parseFuturesOrder()` function with comprehensive tests.

## Context

@.planning/phases/02-csv-import-pipeline/02-RESEARCH.md (Format 6 section, futures_order field mapping)
@packages/shared/src/types/transaction.ts

## Feature

<feature>
  <name>Futures Order History CSV Parser</name>
  <files>
    packages/backend/src/import/parsers/futures-order.ts
    packages/backend/src/import/parsers/futures-order.test.ts
  </files>
  <behavior>
    The `parseFuturesOrder(rows: Record<string, string>[], filename: string)` function accepts pre-parsed CSV rows and returns `{ transactions: ParsedFuturesOrder[], errors: ImportFileError[] }`.

    ParsedFuturesOrder shape:
    ```typescript
    interface ParsedFuturesOrder {
      orderId: string;          // from 'Order ID' column, tab-stripped
      tradedAt: string;         // from 'Date' column
      coin: string;             // from 'Coin' column (settlement coin)
      futures: string;          // from 'Futures' column (trading pair, e.g., 'BTCUSDT')
      rawType: string;          // from 'Direction' column (e.g., 'Open long', 'Close short')
      orderSource: string;      // from 'order source' column
      transactionType: string;  // from 'Transaction type' column
      price: string;            // from 'Average Price' column (may be empty for Market orders)
      amount: string;           // from 'Order amount' column
      executed: string;         // from 'Executed' column
      tradingVolume: string;    // from 'Trading volume' column
      realizedPnl: string;      // from 'Realized P/L' column
      netProfits: string;       // from 'NetProfits' column
      status: string;           // from 'Status' column
      sourceFile: string;
    }
    ```

    Headers: `Date,Order ID,Direction,Coin,Futures,order source,Transaction type,Price,Average Price,Order amount,Executed,Trading volume,Realized P/L,NetProfits,Status`

    Test cases:
    - Open long order -> rawType 'Open long', futures 'BTCUSDT'
    - Close long order -> rawType 'Close long', realizedPnl captured
    - Open short order -> rawType 'Open short'
    - Close short order -> rawType 'Close short', netProfits captured
    - Market order with empty Average Price -> price is '', not an error
    - Filled order -> status 'Filled'
    - Row with missing Order ID -> error
    - Row with missing Date -> error
    - Row with missing Direction -> error
    - Realized P/L is '0' for open orders -> captured as '0'
    - Tab-stripped order ID
    - Multiple mixed valid/invalid rows
  </behavior>
  <implementation>
    1. Create `packages/backend/src/import/parsers/futures-order.ts`
    2. Define `ParsedFuturesOrder` interface and `parseFuturesOrder` function
    3. Normalize column keys to lowercase
    4. Note: column keys include 'order id' (with space), 'realized p/l' (with /), 'netprofits' (one word)
    5. Validate required fields: 'order id', 'date', 'direction'
    6. Average Price is NOT required — can be empty string for Market orders at open
    7. Use 'direction' as rawType, 'futures' as the symbol/pair
  </implementation>
</feature>

# Plan 02-04: Spot Order History Parser (TDD)

## Objective

Build a parser for Bitget spot order history CSVs using TDD. This format has 13 columns including price data, trading pair decomposition, and direction-based typing.

Purpose: Spot order history provides price information that spot transactions lack. It has a different column structure with Direction instead of Type, and Base Asset/Quote Asset for symbol construction.

Output: `parseSpotOrder()` function with comprehensive tests.

## Context

@.planning/phases/02-csv-import-pipeline/02-RESEARCH.md (Format 5 section, spot_order field mapping)
@packages/shared/src/types/transaction.ts

## Feature

<feature>
  <name>Spot Order History CSV Parser</name>
  <files>
    packages/backend/src/import/parsers/spot-order.ts
    packages/backend/src/import/parsers/spot-order.test.ts
  </files>
  <behavior>
    The `parseSpotOrder(rows: Record<string, string>[], filename: string)` function accepts pre-parsed CSV rows and returns `{ transactions: ParsedSpotOrder[], errors: ImportFileError[] }`.

    ParsedSpotOrder shape:
    ```typescript
    interface ParsedSpotOrder {
      orderId: string;        // from 'Order Id' column, tab-stripped
      tradedAt: string;       // from 'Date' column
      symbol: string;         // derived: baseAsset + '/' + quoteAsset (e.g., 'BTC/EUR')
      baseAsset: string;      // from 'Base Asset' column
      quoteAsset: string;     // from 'Quote Asset' column
      rawType: string;        // from 'Direction' column (e.g., 'Buy', 'Sell')
      orderType: string;      // from 'Type' column (e.g., 'Limit', 'Market')
      price: string;          // from 'Average Price' column (NOT 'Price')
      amount: string;         // from 'Order amount' column
      executed: string;       // from 'Executed' column
      tradingVolume: string;  // from 'Trading volume' column (total value in quote asset)
      status: string;         // from 'Status' column (e.g., 'Filled', 'Partially Filled')
      sourceFile: string;
    }
    ```

    Headers: `Date,Type,Order Id,Trading pair,Base Asset,Quote Asset,Direction,Price,Order amount,Executed,Average Price,Trading volume,Status`

    Test cases:
    - Buy order -> Direction 'Buy', symbol 'BTC/EUR', price from Average Price
    - Sell order -> Direction 'Sell'
    - Limit order -> orderType 'Limit'
    - Market order -> orderType 'Market'
    - Symbol derived from baseAsset/quoteAsset: 'ETH' + 'EUR' -> 'ETH/EUR'
    - Average Price used (not Price column) -> correct price field
    - Row with missing Order Id -> error
    - Row with missing Date -> error
    - Row with missing Direction -> error
    - Partially filled order -> executed != amount, both captured
    - Tab-stripped order ID
  </behavior>
  <implementation>
    1. Create `packages/backend/src/import/parsers/spot-order.ts`
    2. Define `ParsedSpotOrder` interface and `parseSpotOrder` function
    3. Normalize column keys to lowercase
    4. Note: column key for order ID is 'order id' (with space) after lowercase normalization
    5. Validate required fields: 'order id', 'date', 'direction', 'average price', 'order amount'
    6. Derive symbol as `${baseAsset}/${quoteAsset}`
    7. Use 'direction' column value as rawType (not 'type' -- 'type' is the order type like Limit/Market)
  </implementation>
</feature>

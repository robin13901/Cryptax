# Plan 02-03: Futures Transactions Parser (TDD)

## Objective

Build a parser for Bitget futures transaction CSVs using test-driven development. The parser converts raw CSV rows into typed `ParsedFuturesTx` objects, handling all 9 known futures transaction type strings including the Bitget typo.

Purpose: Futures transactions represent open/close/settle operations. The parser must handle signed amounts, the unique column set (Futures, Margin Mode, Wallet balance), and all 9 raw type strings.

Output: `parseFuturesTx()` function with comprehensive tests.

## Context

@.planning/phases/02-csv-import-pipeline/02-RESEARCH.md (Format 3 section, futures_tx field mapping, canonical type mapping)
@packages/shared/src/types/transaction.ts (CanonicalType, SourceType)

## Feature

<feature>
  <name>Futures Transaction CSV Parser</name>
  <files>
    packages/backend/src/import/parsers/futures-tx.ts

  <behavior>
    The `parseFuturesTx(rows: Record<string, string>[], filename: string)` function accepts pre-parsed CSV rows and returns `{ transactions: ParsedFuturesTx[], errors: ImportFileError[] }`.

    ParsedFuturesTx shape:
    ```typescript
    interface ParsedFuturesTx {
      orderId: string;        // from 'Order' column, tab-stripped
      tradedAt: string;       // from 'Date' column
      coin: string;           // from 'Coin' column (settlement coin, e.g., 'USDT')
      futures: string;        // from 'Futures' column (trading pair, e.g., 'POPCATUSDT')
      marginMode: string;     // from 'Margin Mode' column
      rawType: string;        // from 'Type' column (e.g., 'open_long', 'close_short')
      amount: string;         // from 'Amount' column, signed
      fee: string;            // from 'Fee' column
      walletBalance: string;  // from 'Wallet balance' column
      sourceFile: string;
    }
    ```

    Headers (comma-delimited): `Order,Date,Coin,Futures,Margin Mode,Type,Amount,Fee,Wallet balance`

    Test cases:
    - open_long row -> all fields mapped correctly
    - close_short row -> signed amount captured
    - burst_close_short row -> rawType preserved as 'burst_close_short'
    - contract_main_settle_fee row -> funding rate
    - trans_from_exchange row -> transfer from spot
    - transfer_from_future_copytrade row
    - risk_captital_user_transfer row -> Bitget typo preserved exactly as 'risk_captital_user_transfer'
    - Row with missing Order -> error
    - Row with missing Date -> error
    - Row with empty Type -> error
    - Multiple rows with mix of valid/invalid -> correct split between transactions and errors
  </behavior>
  <implementation>
    1. Create `packages/backend/src/import/parsers/futures-tx.ts`
    2. Define `ParsedFuturesTx` interface and `parseFuturesTx` function
    3. Normalize column keys to lowercase for case-insensitive access
    4. Validate required fields: 'order', 'date', 'type', 'amount'
    5. Map valid rows to ParsedFuturesTx, invalid to errors array
    6. Use `futures` column for the trading pair symbol (e.g., 'POPCATUSDT'), `coin` for settlement asset
    7. rawType is stored as-is (no mapping -- normalization happens in plan 02-07)
  </implementation>
</feature>

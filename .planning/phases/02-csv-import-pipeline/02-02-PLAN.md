# Plan 02-02: Spot Transactions Parser (TDD)

## Objective

Build a parser for Bitget spot transaction CSVs (both 2024 semicolon-delimited and 2025 comma-delimited formats) using test-driven development. The parser converts raw CSV rows into typed `ParsedSpotTx` objects.

Purpose: Spot transactions are the primary import format (~1461 rows across 2024+2025). Both delimiter variants must parse identically.

Output: `parseSpotTx()` function with comprehensive tests, following TDD red-green-refactor cycle.

## Feature

<feature>
  <name>Spot Transaction CSV Parser</name>
  <files>
    packages/backend/src/import/parsers/spot-tx.ts
    packages/backend/src/import/parsers/spot-tx.test.ts
  </files>
  <behavior>
    The `parseSpotTx(rows: Record<string, string>[], filename: string)` function accepts pre-parsed CSV rows (output of csv-parse/sync with `columns: true, trim: true, bom: true`) and returns `{ transactions: ParsedSpotTx[], errors: ImportFileError[] }`.

    ParsedSpotTx shape:
    ```typescript
    interface ParsedSpotTx {
      orderId: string;        // from 'order' column, tab already stripped by csv-parse trim
      tradedAt: string;       // from 'Date' column, as-is (e.g., '2024-12-31 23:17:21')
      symbol: string;         // from 'Coin' column (e.g., 'USDE', 'EUR', 'BTC')
      rawType: string;        // from 'Type' column, as-is (e.g., 'Buy', 'Sell', 'Interest')
      amount: string;         // from 'Amount' column, signed string (e.g., '-37.06153', '0.00032')
      fee: string;            // from 'Fee' column (e.g., '0', '0.001')
      available: string;      // from 'Available' column, running balance
      sourceFile: string;     // the filename parameter
    }
    ```

    Test cases:
    - Basic Buy row -> orderId trimmed, amount positive, fee '0'
    - Basic Sell row -> amount negative
    - Interest row -> rawType 'Interest', amount positive
    - Row with all columns filled (happy path)
    - Row with missing orderId -> error in errors array, not in transactions
    - Row with missing Date -> error in errors array
    - Row with empty Amount -> error in errors array
    - Multiple rows -> all valid rows in transactions, invalid rows in errors
    - 2024 semicolon format fixture (actual row) -> parsed correctly
    - 2025 comma format fixture (actual row) -> parsed identically
    - Order ID with tab prefix already stripped by csv-parse -> no leading \t
  </behavior>
  <implementation>
    1. Create `packages/backend/src/import/parsers/spot-tx.ts`
    2. Define `ParsedSpotTx` interface and `parseSpotTx` function
    3. For each row in the input array:
       - Validate required fields: 'order' (or 'Order'), 'Date', 'Coin', 'Type', 'Amount'
       - If any required field is missing or empty, push to errors with row index, field name, message
       - Otherwise, map to ParsedSpotTx object and push to transactions
    4. The function does NOT do normalization (canonical type mapping, checksum, etc.) -- that's Plan 02-07's job
    5. Column access: use lowercase-normalized keys since csv-parse `columns: true` preserves original case. Access as `row['order']` or `row['Order']` -- handle case-insensitively by normalizing keys on input.

    Key decision: Normalize all CSV column keys to lowercase at parse time to handle case variations across files. The function should accept `Record<string, string>[]` where keys may be mixed-case, and internally normalize them.
  </implementation>
</feature>

  <action>
    Create `resolution-strategy.ts` that exports `resolvePrice`:

    ```typescript
    interface ResolutionResult {
      eurPrice: string;            // Decimal string
      source: PriceSource;         // 'csv-fill' | 'bitget-direct' | 'bitget-usdt' | 'coingecko'
      usdtPrice?: string;          // only for bitget-usdt
      usdtEurRate?: string;        // only for bitget-usdt
    }

    interface ResolutionFailure {
      reason: PriceFailureReason;  // 'no-bitget-pair' | 'coingecko-miss' | 'api-error'
    }

    type ResolutionOutcome = { ok: true; result: ResolutionResult } | { ok: false; failure: ResolutionFailure };
    ```

    `resolvePrice(tx, deps)` takes a transaction row and dependency-injected clients:

    ```typescript
    interface ResolutionDeps {
      bitgetClient: { fetchClose: (symbol: string, targetMs: number, granularity?: '1min' | '5min') => Promise<string | null> };
      coingeckoClient: { fetchPrice: (coinId: string, utcMs: number) => Promise<string | null> };
      symbolMap: Map<string, string>;  // CoinGecko symbol -> ID map
      cache: { lookup: typeof lookupPriceCache; upsert: typeof upsertPriceCache };
      db: any;  // Drizzle DB instance for cache operations
    }
    ```

    **Fallback chain (in order):**

    1. **CSV fill-price shortcut:** If `usesCsvFillPrice(tx.sourceType, tx.symbol, tx.price)` returns true, return `{ eurPrice: tx.price, source: 'csv-fill' }` immediately. No API call, no cache write needed.

    2. **Cache lookup:** Call `lookupPriceCache(db, parsedSymbol.bitgetSymbol, timestampMinute)`. If found, return cached result. Do NOT call any API.

    3. **Bitget direct EUR:** Call `bitgetClient.fetchClose(baseAsset + 'EUR', targetMs, '1min')`.
       - If returns a price → source = 'bitget-direct'. Write to cache. Return.
       - If returns null → try 5min granularity: `bitgetClient.fetchClose(baseAsset + 'EUR', targetMs, '5min')`
       - If 5min returns a price → source = 'bitget-direct'. Write to cache. Return.
       - If null → proceed to step 4.

    4. **Bitget USDT fallback:** Call BOTH `bitgetClient.fetchClose(baseAsset + 'USDT', targetMs, '1min')` AND `bitgetClient.fetchClose('USDTEUR', targetMs, '1min')` at the SAME targetMs.
       - If BOTH return prices → eurPrice = `Decimal(baseInUsdt).mul(Decimal(usdtInEur)).toString()`. source = 'bitget-usdt'. Write to cache with usdtPrice + usdtEurRate fields. Return.
       - If either is null → try 5min for both legs.
       - If still null → proceed to step 5.

    5. **CoinGecko fallback:** Look up `parsedSymbol.base.toLowerCase()` in symbolMap. If found:
       - Call `coingeckoClient.fetchPrice(coinId, targetMs)`
       - If returns price → source = 'coingecko'. Write to cache. Return.
       - If throws CoinGeckoOutOfRangeError → return failure: `{ reason: 'coingecko-miss' }`
       - If returns null → return failure: `{ reason: 'coingecko-miss' }`

    6. **All failed:** Return failure: `{ reason: 'no-bitget-pair' }` if Bitget returned 40034-equivalent; `{ reason: 'api-error' }` otherwise.

    **Key rules:**
    - Use `berlinToUtcMs(tx.tradedAt)` for the targetMs conversion
    - Use `parseSymbol(tx.symbol, tx.sourceType)` for base/quote extraction
    - Round timestampMinute to minute precision for cache key: truncate seconds from the UTC ISO string
    - Use Decimal.js for USDT multiplication — NEVER native float arithmetic
    - Both USDT fallback legs MUST use the same targetMs

    **Tests (mock all external deps):**
    - CSV fill shortcut: spot_order with EUR pair → returns csv-fill immediately, no client calls
    - Cache hit: lookup returns entry → returns cached result, no client calls
    - Bitget direct 1min success: returns bitget-direct
    - Bitget direct 1min fail, 5min success: returns bitget-direct
    - USDT fallback: both legs succeed → returns bitget-usdt with correct Decimal multiplication
    - USDT fallback: one leg fails → falls through to CoinGecko
    - CoinGecko success: returns coingecko
    - CoinGecko out-of-range: returns failure with 'coingecko-miss'
    - All sources fail: returns failure with appropriate reason
    - Cache write: verify upsertPriceCache called after successful API resolution
    - Same targetMs for both USDT legs: verify both calls use identical timestamp

    Create `enrichment-engine.ts` that exports `runEnrichment`:

    ```typescript
    interface EnrichmentProgress {
      total: number;
      processed: number;
      resolved: number;
      failed: number;
      currentSymbol: string;
      currentSource: string;  // which source is being tried
    }

    interface EnrichmentResult {
      total: number;
      resolved: number;
      failed: number;
      skippedCacheHit: number;
      bySource: Record<PriceSource, number>;  // count per source
      failures: Array<{ transactionId: number; symbol: string; reason: PriceFailureReason }>;
    }
    ```

    `runEnrichment(db, deps, onProgress?)`:

    1. **Select unresolved transactions:**
       ```sql
       SELECT * FROM transactions
       WHERE eur_price IS NULL OR price_source = 'manual'
       ORDER BY traded_at ASC
       ```
       The `OR price_source = 'manual'` clause ensures manual entries are overwritten by API prices per CONTEXT decision.

    2. **Load CoinGecko symbol map** (once, at start): `deps.coingeckoClient.loadSymbolMap()`

    3. **Iterate transactions sequentially** (rate limiting handles parallelism internally):
       For each transaction:
       a. Call `resolvePrice(tx, deps)` with the loaded symbolMap
       b. If `ok: true`:
          - UPDATE transactions SET eurPrice = result.eurPrice, priceSource = result.source, priceResolvedAt = new Date().toISOString(), priceFailureReason = NULL
       c. If `ok: false`:
          - UPDATE transactions SET priceFailureReason = failure.reason, priceSource = NULL, eurPrice = NULL, priceResolvedAt = NULL
       d. Emit `onProgress(progress)` after each transaction

    4. **Return EnrichmentResult** with counts and failure details.

    **Key rules:**
    - Process transactions one at a time (rate limiter inside clients handles concurrency)
    - Update each transaction immediately after resolution (not batch at end) — so progress is visible in the DB
    - Never throw — individual transaction failures are recorded but don't stop the run
    - If a transaction resolution throws unexpectedly, catch it, record as 'api-error', continue

    **Tests (mock all deps including DB):**
    - Empty unresolved set → returns immediately with all zeros
    - 3 transactions: 1 csv-fill, 1 bitget-direct, 1 coingecko → correct counts in result
    - 2 transactions: 1 resolves, 1 fails → both reflected in result; failure recorded
    - Manual entry overwritten: transaction with price_source='manual' included in unresolved set
    - Progress callback: verify called once per transaction with incrementing processed count
    - Exception in resolvePrice: caught, recorded as api-error, continues to next tx
    - EnrichmentResult.bySource: correct breakdown per source type

    Run `npx biome format --write` and `npx vitest run`.

  <action>
    Create `packages/backend/src/prices/` directory.

    **timezone.ts:**
    Export `berlinToUtcMs(tradedAt: string): number` that:
    - Takes a `"YYYY-MM-DD HH:mm:ss"` string in Europe/Berlin local time
    - Uses `fromZonedTime` from `date-fns-tz` (v3 API, NOT the deprecated `zonedTimeToUtc`)
    - Returns UTC milliseconds (number)
    - Handles DST spring-forward: `"2024-03-31 02:30:00"` (non-existent Berlin time) resolves using CET (UTC+1) offset, producing 2024-03-31T01:30:00.000Z = 1711845000000
    - NOTE: Use `fromZonedTime(tradedAt.replace(' ', 'T'), 'Europe/Berlin')` — the space-to-T replacement ensures the date string is parsed as a date-time, not a date.

    **timezone.test.ts:**
    Test cases (at minimum):
    - Standard CET time: "2024-01-15 14:30:00" → verify UTC is 13:30 (CET = UTC+1)
    - Standard CEST time: "2024-07-15 14:30:00" → verify UTC is 12:30 (CEST = UTC+2)
    - DST spring-forward gap: "2024-03-31 02:30:00" → non-existent time, verify resolves to UTC+1 (01:30 UTC)
    - DST fall-back: "2024-10-27 02:30:00" → ambiguous time, verify consistent resolution
    - Midnight boundary: "2024-01-01 00:00:00" → 2023-12-31T23:00:00Z

    **symbol-parser.ts:**
    Export `parseSymbol(symbol: string, sourceType: SourceType): ParsedSymbol` where:
    ```typescript
    interface ParsedSymbol {
      base: string;           // e.g., "BTC"
      quote: string | null;   // e.g., "EUR", "USDT", null for spot_tx
      bitgetSymbol: string;   // e.g., "BTCEUR" — base+quote concatenated
    }
    ```

    Logic per sourceType:
    - `spot_order`: split on `/` → `{ base: "BTC", quote: "EUR", bitgetSymbol: "BTCEUR" }`
    - `spot_tx`: bare coin name → `{ base: "BTC", quote: null, bitgetSymbol: "BTCEUR" }` (default to EUR as quote for Bitget lookup)
    - `futures_order` / `futures_tx`: strip known quote suffixes (USDT, USD, EUR, BTC, PERP) → extract base. e.g., "BTCUSDT" → `{ base: "BTC", quote: "USDT", bitgetSymbol: "BTCUSDT" }`
    - `earn`: bare coin name (same as spot_tx) → `{ base: "ETH", quote: null, bitgetSymbol: "ETHEUR" }`

    Also export `usesCsvFillPrice(sourceType: SourceType, symbol: string, price: string): boolean`:
    - Returns true when `sourceType === 'spot_order'` AND symbol contains `/EUR` (quote is EUR) AND price is not '0' and not empty.
    - This detects spot orders where the CSV already has the EUR fill price.

    **symbol-parser.test.ts:**
    Test cases:
    - spot_order: "BTC/EUR" → base BTC, quote EUR, bitgetSymbol BTCEUR
    - spot_order: "ETH/USDT" → base ETH, quote USDT, bitgetSymbol ETHUSDT
    - spot_tx: "BTC" → base BTC, quote null, bitgetSymbol BTCEUR
    - futures_order: "BTCUSDT" → base BTC, quote USDT, bitgetSymbol BTCUSDT
    - futures_order: "ETHUSDT" → base ETH, quote USDT
    - futures_tx: "BTCUSDT" → same as futures_order
    - earn: "ETH" → base ETH, quote null, bitgetSymbol ETHEUR
    - CSV fill price: spot_order + "BTC/EUR" + price "45000" → true
    - CSV fill price: spot_order + "BTC/USDT" + price "45000" → false (not EUR pair)
    - CSV fill price: spot_order + "BTC/EUR" + price "0" → false (no price)
    - CSV fill price: spot_tx + "BTC" + price "0" → false (wrong source type)

    Run `npx biome format --write` on all new files. Then run `npx vitest run` to ensure all tests pass.
  </action>

  </done>

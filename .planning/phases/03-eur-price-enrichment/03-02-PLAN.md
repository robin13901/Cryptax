<feature>
  <name>Bitget Candle API Client</name>
  <files>packages/backend/src/prices/bitget-client.ts, packages/backend/src/prices/bitget-client.test.ts</files>
  <behavior>
    fetchBitgetCandleClose(symbol, targetMs, granularity?) -> string | null

    Cases:
    - ("BTCEUR", 1711900620000, "1min") -> "65432.10" (close price from closest candle)
    - ("BTCEUR", targetMs, "1min") when API returns code "40034" -> null (pair doesn't exist)
    - ("BTCEUR", targetMs, "1min") when API returns empty data array -> null
    - ("BTCEUR", targetMs, "1min") when API returns multiple candles -> picks closest to targetMs
    - ("BTCEUR", targetMs, "5min") -> uses 5min granularity parameter
    - ("BTCEUR", targetMs) when network error -> null (never throws)

    createBitgetClient() -> { fetchClose: throttled version at 10 req/s }
    - Wraps fetchBitgetCandleClose with p-throttle({ limit: 10, interval: 1000 })
    - Accepts optional fetch function parameter for testing (dependency injection)
  </behavior>
  <implementation>
    1. Create bitget-client.ts:
       - `BITGET_BASE_URL = 'https://api.bitget.com'`
       - `fetchBitgetCandleClose(symbol, targetMs, granularity = '1min', fetchFn = globalThis.fetch)`:
         - Build URL: `/api/v2/spot/market/history-candles`
         - Params: symbol, granularity, endTime = String(targetMs + 60_000), limit = '5'
         - Parse response: code "00000" = success, "40034" = pair not found
         - Find closest candle by comparing |candle[0] - targetMs|
         - Return candle[4] (close price as string) or null
         - Wrap entire function in try-catch — network errors return null, never throw
       - `createBitgetClient(fetchFn?)`: returns `{ fetchClose }` where fetchClose is throttled via p-throttle

    2. Use dependency injection for fetch (pass `fetchFn` parameter) so tests can mock HTTP without intercepting global fetch.

    3. Tests mock fetch to return predetermined JSON responses. Test:
       - Success with single candle
       - Success with multiple candles (verify closest-to-target selection)
       - Error code 40034 (symbol not found)
       - Empty data array
       - Network error (fetch throws)
       - 5min granularity parameter forwarded correctly
       - URL construction (verify endTime = targetMs + 60000, limit = 5)
  </implementation>
</feature>

<feature>
  <name>Price Cache Layer</name>
  <files>packages/backend/src/prices/price-cache.ts, packages/backend/src/prices/price-cache.test.ts</files>
  <behavior>
    lookupPriceCache(db, symbol, timestampMinute) -> PriceCacheEntry | null

    Cases:
    - ("BTCEUR", "2024-03-31T10:23:00.000Z") with matching row -> { eurPrice, source, usdtPrice?, usdtEurRate? }
    - ("BTCEUR", "2024-03-31T10:23:00.000Z") with no matching row -> null

    upsertPriceCache(db, entry) -> void

    Cases:
    - New entry -> inserts successfully
    - Duplicate (symbol, timestamp, source) -> does NOT throw (onConflictDoNothing)
    - Entry with usdtPrice and usdtEurRate -> stores both USDT fields
  </behavior>
  <implementation>
    1. Create price-cache.ts:
       - `lookupPriceCache(db, symbol: string, timestampMinute: string)`:
         - Query: `SELECT * FROM price_cache WHERE symbol = ? AND timestamp = ? LIMIT 1`
         - Use Drizzle `db.select().from(priceCache).where(and(eq(symbol), eq(timestamp)))`
         - Return first result or null
       - `upsertPriceCache(db, entry: PriceCacheInsert)`:
         - Use `db.insert(priceCache).values({...}).onConflictDoNothing()`
         - Entry includes: symbol, timestamp (minute-precision UTC ISO), eurPrice, source, usdtPrice?, usdtEurRate?, fetchedAt (ISO string)

    2. Export `PriceCacheEntry` and `PriceCacheInsert` types.

    3. Tests use DB_PATH=':memory:' with Drizzle migrations applied:
       - Cache miss returns null
       - Insert then lookup returns correct entry
       - Duplicate insert does not throw (onConflictDoNothing)
       - USDT fallback fields stored and retrieved
       - Multiple sources for same symbol+timestamp stored separately (unique key includes source)
  </implementation>
</feature>

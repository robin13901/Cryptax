    - Create a Hono app instance and register ALL routes (import, engine, summary, report)

      - Insert a set of transactions covering: spot buys, spot sells (some with haltefrist met, some not), futures closes, earn income events
      - Ensure EUR prices are populated on all transactions
      - Run the engine via POST /api/engine/run (or call the orchestrator directly)

    **Alternatively (simpler approach):** Directly seed the derived tables (tax_summaries, lot_consumptions, fifo_lots, futures_positions, earn_income) without running the engine. This tests the report pipeline in isolation without coupling to engine internals. Choose whichever approach is more robust.

    **Tests:**

    1. `GET /api/report/years returns available years`:
       - Seed data for 2024
       - Assert response contains [2024]

    2. `GET /api/report/2024/preview returns complete ReportData`:
       - Assert 200 response
       - Assert response has spotSummary with correct netEur matching seeded data
       - Assert response has futuresSummary with estimatedTaxEur > 0
       - Assert response has earnSummary with totalIncomeEur > 0
       - Assert tradeAppendix.length matches expected lot consumption count

    3. `GET /api/report/2024/pdf returns valid PDF`:
       - Assert 200 with Content-Type: application/pdf
       - Assert body is a Buffer starting with %PDF-
       - Assert body length > 1000 (non-trivial PDF)

    4. `GET /api/report/2024/csv returns valid CSV`:
       - Assert 200 with Content-Type containing text/csv
       - Parse the CSV body: split by lines, split first line by ';'
       - Assert header has 13 columns
       - Assert data row count matches tradeAppendix length
       - Assert contains "Zusammenfassung" in the summary section

    5. `Preview data matches PDF content (cross-format consistency)`:
       - Compare preview JSON spotSummary.netEur with a substring search in the PDF buffer — the formatted EUR value should appear in both

    6. `Report for non-existent year returns 404`:
       - GET /api/report/2099/preview -> 404
       - GET /api/report/2099/pdf -> 404
       - GET /api/report/2099/csv -> 404

    IMPORTANT: This test requires the application to be running with a real database. The test imports CSV fixtures, runs the engine, and then tests the report flow.

    ```typescript
    import { test, expect } from '@playwright/test';
    import path from 'path';

    test.describe('Steuerreport E2E', () => {

      test('Steuerreport tab shows empty state initially', async ({ page }) => {
        await page.goto('/');
        await page.getByRole('button', { name: 'Steuerreport' }).click();
        // Should show empty state or year selector with no data
        await expect(page.getByText(/Keine Daten|Steuerreport/)).toBeVisible();
      });

      test('Full flow: import -> engine -> report preview -> PDF download', async ({ page }) => {
        await page.goto('/');

        // Step 1: Navigate to Transaktionen tab and import CSV
        await page.getByRole('button', { name: 'Transaktionen' }).click();

        // Open the import section (it's in a <details> toggle)
        await page.getByText('Import & Preise').click();

        // Upload a test CSV fixture via the file input
        // Use one of the existing Bitget CSV test fixtures
        const csvPath = path.resolve('raw-bitget-exports');
        // Find a spot transactions CSV file to upload
        const fileInput = page.locator('input[type="file"]');
        // If drag-and-drop zone has a file input, use it
        // The ImportDropzone has a hidden file input — use setInputFiles
        const csvFiles = await page.locator('input[type="file"]').all();
        if (csvFiles.length > 0) {
          // Upload a test CSV — adjust path to actual fixture
          // This may need adjustment based on actual fixture filenames
          await csvFiles[0].setInputFiles(path.resolve('raw-bitget-exports/spot_transactions_2024.csv'));
        }

        // Wait for import to complete — look for import summary
        await expect(page.getByText(/importiert|Import/)).toBeVisible({ timeout: 15_000 });

        // Step 2: Run price enrichment (if needed — skip if prices already populated)
        // Step 3: Run tax engine
        // Look for "Berechnung starten" or "Engine" button
        // The engine is triggered from the Dashboard or a separate control
        // This may need to be done via API call if no UI button exists:
        await page.request.post('http://localhost:3001/api/engine/run');

        // Step 4: Switch to Steuerreport tab
        await page.getByRole('button', { name: 'Steuerreport' }).click();

        // Wait for preview to load
        await page.waitForTimeout(2000);

        // Step 5: Verify preview sections are visible
        // Note: The exact text depends on whether data was imported successfully
        // and engine ran. If the E2E environment has no real data, these assertions
        // may need adjustment.

        // Step 6: Test PDF download
        const downloadPromise = page.waitForEvent('download');
        const pdfButton = page.getByRole('button', { name: /PDF herunterladen/i });
        if (await pdfButton.isVisible()) {
          await pdfButton.click();
          const download = await downloadPromise;
          expect(download.suggestedFilename()).toMatch(/cryptax-steuerreport-\d{4}\.pdf/);
        }
      });
    });
    ```

    **Note on E2E test pragmatism:** The full flow test (import -> engine -> report) depends on having actual CSV test fixtures in `raw-bitget-exports/`. If those files are not committed to git (they're in .gitignore), the E2E test should be structured to:
    1. Check if fixtures exist, skip gracefully if not
    2. OR use a minimal test fixture created in the e2e/ directory
    3. OR test only the empty state + UI interaction (without full data flow)

    Create a minimal test fixture `e2e/fixtures/test-spot-2024.csv` with 3-5 rows of valid spot transaction data if the raw exports are not available in CI.

    The E2E tests are primarily for local verification. They can be excluded from CI if fixtures are not available (add `test.skip` condition or a CI environment check).

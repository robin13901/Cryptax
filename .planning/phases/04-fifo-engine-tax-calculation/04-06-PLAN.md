  <action>
Create `packages/backend/src/engine/tax-calculator.ts` with the main `runTaxCalculation(db: Db): TaxCalculationResult` function.

**Orchestration flow:**

1. **NULL price gate**: Call `checkNullPrices(db)`. If non-empty, return immediately with error result containing the list of transactions with missing prices. Do NOT proceed with computation.

2. **Load all transactions**: Query all transactions from the `transactions` table, ordered by `tradedAt` ASC. Map to `EngineTransaction[]`.

3. **Truncate derived tables** (inside a `db.transaction()` with `behavior: 'immediate'`):
   - Delete order must respect FK constraints: `lotConsumptions` -> `fifoLots` -> `futuresPositions` -> `earnIncome` -> `taxSummaries`
   - Use `db.delete(table).run()` for each table (no `.where()` = delete all)

4. **Route transactions to engines**:
   - Earn engine runs FIRST (because it creates FIFO lots that spot engine needs):
     `const earnResult = runEarnIncomeEngine(allTransactions)`
   - FIFO engine receives spot buy/sell transactions PLUS earn-created lots:
     The FIFO engine takes `EngineTransaction[]` — for earn lots, we need to convert earnResult.lotsCreated back into synthetic buy transactions so the FIFO engine can include them in the lot pool. OR, better approach: the FIFO engine takes transactions, and the orchestrator also passes the earn lots separately to be merged into the lot pool.
   - ACTUALLY, simplest approach: Run FIFO engine on all buy+sell transactions. Then merge earn lots into the FIFO lot pool. But the FIFO engine returns the lot pool, so we need to add earn lots to it. The spot-tax-calculator just needs consumption records.
   - CLEANEST approach: The FIFO engine processes buy/sell. Earn engine creates lots. The orchestrator merges earn lots with FIFO lots before writing to DB. If a sell happens after an earn, the FIFO engine's lot pool already handles chronological ordering — BUT only if earn lots are fed as buys. So: prepend earn transactions as synthetic buys into the FIFO engine input. Create synthetic `EngineTransaction` entries for each earn transaction with canonicalType='buy', then let the FIFO engine process them naturally.

   **DECISION: Feed earn transactions into FIFO engine as buy-equivalents:**
   - Take earn transactions (earn_interest, earn_deposit) and create synthetic buy entries for the FIFO engine
   - Set canonicalType='buy' on these synthetics so the FIFO engine creates lots
   - This handles cross-year continuity automatically (earn in 2024, sell in 2025)
   - The earn income engine still runs separately for income tracking (section 22 records)

   Implementation:
   ```
   a) Run earnIncomeEngine on all transactions → get income records
   b) Create synthetic buy transactions from earn transactions (same fields, canonicalType='buy')
   c) Combine original buy/sell transactions + synthetic earn-buys
   d) Run fifoEngine on combined transactions → gets lots + consumptions
   e) Run futuresPnlEngine on all transactions → gets futures P&L
   f) Run calculateSpotTax on FIFO consumptions → get per-year spot tax
   ```

5. **Write results to DB** (still inside the transaction):
   - Insert all FIFO lots into `fifoLots` table. Use `fromDecimal()` for Decimal fields. Map InMemoryLot fields to schema columns (originalAmount, remainingAmount, costBasisEur, costPerUnitEur, feeEur, acquiredAt, transactionId, taxYear, symbol).
   - After inserting lots, get their auto-increment IDs. Map lot array indices to DB IDs.
   - Insert all consumption records into `lotConsumptions` table. Map ConsumptionRecord fields to schema columns. The `lotId` comes from the DB ID of the corresponding lot (use the lotIndex from ConsumptionRecord to look up the inserted lot's ID).
   - Insert futures positions into `futuresPositions` table.
   - Insert earn income records into `earnIncome` table.

6. **Generate and write tax summaries**:
   - For each year, create up to 3 tax_summaries rows (one per bucket):
     - **private_sale (section 23)**: From spotTaxResult for that year. totalGainsEur, totalLossesEur, netEur, taxableAmountEur (after Freigrenze), estimatedTaxEur = '0' (Einkommensteuer rate varies per person — cannot estimate), tradeCount.
     - **futures_pnl (section 20)**: Aggregate futuresPnlResult positions for that year. totalGainsEur = sum of positive realizedPnlEur, totalLossesEur = sum of negative. netEur = total. If net > 0: estimatedTaxEur = net * ABGELTUNGSSTEUER_RATE. taxableAmountEur = netEur (no Freigrenze for futures). TotalFeesEur: sum of feeEur. Reduce net by fees before computing tax.
     - **staking_earn (section 22 Nr. 3)**: Aggregate earnResult income for that year. totalGainsEur = sum of eurValueAtReceipt. netEur = totalGainsEur. Apply 256 EUR Freigrenze cliff: if net <= 256, taxableAmountEur = '0'; if > 256, taxableAmountEur = netEur (full amount). estimatedTaxEur = '0' (Einkommensteuer rate varies).
   - Insert into `taxSummaries` table. `computedAt = new Date().toISOString()`.

7. **Return TaxCalculationResult** with all engine results + summaries + errors.

Use Drizzle's `db.insert(table).values(row).run()` for single inserts, or `.values(rows)` for batch inserts.
All monetary values must be converted from Decimal to string via `fromDecimal()` before DB insertion.

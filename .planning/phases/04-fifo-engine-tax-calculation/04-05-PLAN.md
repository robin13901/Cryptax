<objective>
Implement the earn income engine using TDD — handles both income recognition and FIFO lot creation.

Purpose: Earn/staking income has dual tax treatment in German law: (1) taxable income under section 22 Nr. 3 EStG at EUR value when received, and (2) creates a new FIFO lot for the received coins so they can be tracked for later disposal. This engine handles both.

Output: Working earn-income-engine.ts with tests proving dual treatment and 256 EUR Freigrenze.
</objective>

  <behavior>
The earn income engine processes earn/staking transactions and produces both income records and FIFO lots.

**Function signature:**
`runEarnIncomeEngine(transactions: EngineTransaction[]): EarnIncomeResult`

Pure function. Takes all transactions, filters to earn types, returns income records + FIFO lots.

**Processing rules:**

1. Filter to earn canonical types: `earn_interest`, `earn_deposit`. Skip all others (add to skipped with reason). Explicitly skip `earn_withdrawal` (internal Bitget transfer, not taxable).

2. For each earn transaction:
   - Normalize symbol to base asset using `parseSymbol(tx.symbol, tx.sourceType).base`
   - EUR value at receipt = `toDecimal(tx.eurPrice).times(toDecimal(tx.amount))`
   - Record income: `{ transactionId: tx.id, symbol: baseAsset, amount: tx.amount, eurValueAtReceipt: fromDecimal(eurValue), receivedAt: tx.tradedAt, taxYear: tx.taxYear }`

3. For each earn transaction, also create a FIFO lot:
   - `originalAmount = toDecimal(tx.amount)`
   - `remainingAmount = originalAmount` (not yet consumed)
   - `costPerUnitEur = toDecimal(tx.eurPrice)` (cost basis = fair market value at receipt)
   - `feeEur = ZERO` (earn transactions have no acquisition fee)
   - `acquiredAt = tx.tradedAt`
   - `taxYear = tx.taxYear`
   - `symbol = baseAsset`

4. The earn Freigrenze (256 EUR) is NOT applied in this engine. It is applied at the summary/orchestrator level per-year. This engine just records raw income. The orchestrator will aggregate and check: if annual earn income <= 256 EUR, taxable = 0; if > 256, full amount is taxable (cliff behavior).

**Note on Freigrenze location:** The 256 EUR Freigrenze for earn income is a per-year aggregate check, not per-transaction. The earn engine records all income. The tax-calculator orchestrator (plan 04-06) sums per year and applies the cliff.

**Test cases (RED phase):**

- `records income for earn_interest transaction`: Stake 1 ETH, eurPrice=3000. Assert income record: eurValueAtReceipt = '3000'.
- `records income for earn_deposit transaction`: Deposit 0.5 BTC, eurPrice=50000. Assert income = '25000'.
- `creates FIFO lot for each earn transaction`: Earn 1 ETH. Assert lot created with costPerUnitEur = eurPrice, feeEur = '0'.
- `FIFO lot has correct cost basis`: Earn 2 ETH at eurPrice=1500. Assert lot: originalAmount=2, costPerUnitEur=1500, costBasisEur=3000.
- `skips earn_withdrawal`: earn_withdrawal transaction. Assert skipped with reason.
- `skips non-earn transactions`: buy, sell, futures types. Assert all in skipped array.
- `processes multiple earn transactions`: 3 earn events. Assert 3 income records + 3 FIFO lots.
- `normalizes symbol from earn source type`: "ETH" from earn source. Assert symbol = "ETH".
- `handles zero eurPrice gracefully`: Earn with eurPrice = '0' (edge case — shouldn't happen after null gate but be defensive). Assert eurValueAtReceipt = '0', lot created with zero cost.
  </behavior>

Create `packages/backend/src/engine/golden-master.test.ts` with hand-verified tax scenarios that serve as regression tests.

Each scenario sets up an in-memory DB with transactions, runs `runTaxCalculation(db)`, and verifies exact numeric results.

**Scenario 1: 3 BTC buys, 1 partial sell crossing two lots, one lot Haltefrist-met** (Success Criteria #1)

Setup:
- Buy 0.5 BTC on 2023-06-01 at eurPrice=25000 (taxYear 2023) → Lot A: costBasis = 12500 EUR
- Buy 0.3 BTC on 2024-01-15 at eurPrice=40000 (taxYear 2024) → Lot B: costBasis = 12000 EUR
- Buy 0.2 BTC on 2024-07-01 at eurPrice=55000 (taxYear 2024) → Lot C: costBasis = 11000 EUR
- Sell 0.7 BTC on 2024-08-01 at eurPrice=60000 (taxYear 2024) → Proceeds = 42000 EUR

Expected FIFO consumption:
- Lot A (0.5 BTC): Held from 2023-06-01 to 2024-08-01 = 427 days >= 366 → Haltefrist met → TAX-FREE
  - Consumed: 0.5 BTC, costBasis=12500, proceeds=30000, gain=17500 (tax-free)
- Lot B (0.2 BTC consumed): Held from 2024-01-15 to 2024-08-01 = 199 days < 366 → TAXABLE
  - Consumed: 0.2 BTC, costBasis=8000, proceeds=12000, gain=4000 (taxable)

Verify:
- fifo_lots: 3 lots, Lot A remaining=0, Lot B remaining=0.1, Lot C remaining=0.2
- lot_consumptions: 2 records (Lot A + Lot B)
- Lot A consumption: haltefristMet=true, gain = 17500
- Lot B consumption: haltefristMet=false, gain = 4000
- tax_summaries for 2024 private_sale: taxFreeGain includes 17500, taxableAmountEur based on 4000 net (which is > 1000, so full 4000 is taxable)

**Scenario 2: Freigrenze boundary tests** (Success Criteria #3)

Setup 3 sub-scenarios (can be separate test cases):

a) Net gain = 999.99 EUR:
- Buy 1 BTC at eurPrice=50000 (2024)

- Assert taxableAmountEur = '0'

b) Net gain = 1000.00 EUR:
- Buy 1 BTC at eurPrice=50000

c) Net gain = 1000.01 EUR:
- Buy 1 BTC at eurPrice=50000

- Assert taxableAmountEur = '1000.01' (entire amount, not 0.01)

**Scenario 3: Futures isolation** (Success Criteria #2)

Setup:
- Buy 1 BTC, sell 1 BTC (spot)
- futures_close_long with amount='500', eurPrice='1' (500 EUR P&L)

- private_sale totals come only from spot

- No cross-contamination

**Scenario 4: NULL price gate** (Success Criteria #4)

- Insert a buy with eurPrice=null
- Run engine
- Assert error result with the transaction identified
- Assert all derived tables are empty

**Scenario 5: Idempotent re-run** (Success Criteria #5)

- Set up the scenario from #1
- Run engine, capture all tax_summaries rows
- Run engine again, capture all tax_summaries rows again
- Assert the two sets are identical (same values, same row count)

All scenarios must use `toDecimal()` / `fromDecimal()` for expected values to ensure precision. Use Vitest's `describe` / `it` / `expect`. Use `beforeEach` for fresh in-memory DB per test.

2. Create `packages/backend/src/engine/property-tests.test.ts`:

These tests use fast-check to verify FIFO invariants across thousands of random inputs. They test the FIFO engine directly (not the full orchestrator) for speed.

**Property 1: lot.remainingAmount is never negative**

Generate random arrays of buy and sell amounts using `fc.array(fc.double({ min: 0.001, max: 100, noNaN: true }))`. For each generated set:
- Create synthetic EngineTransaction[] with buys of random amounts
- Create sells with random amounts (capped at total buy amount to avoid expected errors)
- Run `runFifoEngine(transactions)`
- Assert: every lot in result.lots has `remainingAmount.gte(ZERO)` or remainingAmount >= 0

**Property 2: total consumed never exceeds total acquired per asset**

For each generated set:
- Sum all buy amounts per asset
- Sum all consumed amounts per asset (from consumptions)
- Assert: consumed <= acquired for every asset

**Property 3: consumptions are proportional (proceeds + cost basis consistency)**

For each consumption record:
- costBasisEur should approximately equal amountConsumed * lot.costPerUnitEur
- proceedsEur should approximately equal amountConsumed * sellPricePerUnit

**Property 4: lot ordering is FIFO**

Generate buys at sequential timestamps. Generate a sell.
- Assert: the first lot consumed has the earliest acquiredAt among lots with remaining amount

Use `fc.assert()` with `{ numRuns: 100 }` for reasonable test speed. Use `fc.property()` to define properties.

Create helper function `buildSyntheticTransactions(buys: number[], sells: number[]): EngineTransaction[]` that creates EngineTransaction objects with proper fields (sequential timestamps, eurPrice='1' for simplicity, canonicalType='buy'/'sell', sourceType='spot_tx', symbol='BTC').

All monetary comparisons use Decimal.js with appropriate tolerance for rounding (use `closeTo` or check within epsilon if needed).

  <behavior>
The futures P&L engine processes futures transactions and produces per-transaction realized P&L records.

**Function signature:**
`runFuturesPnlEngine(transactions: EngineTransaction[]): FuturesPnlResult`

Pure function — no DB access. Takes all transactions, filters to futures-only, returns P&L records.

**Processing rules:**
1. Filter to futures canonical types only: `futures_close_long`, `futures_close_short`, `futures_fee`, `futures_funding`. Skip `futures_open_long`, `futures_open_short` (opens are not taxable events). Skip all non-futures types.

2. For each `futures_close_long` or `futures_close_short`:
   - The `amount` field from futures_tx represents the realized P&L in the margin currency (USDT typically)
   - The `eurPrice` field is the EUR conversion rate from Phase 3
   - Realized P&L in EUR = `toDecimal(tx.amount).times(toDecimal(tx.eurPrice))`
   - Note: for close_short with a gain, the amount is positive. For close_long with a loss, amount may be negative. Preserve the sign.
   - Normalize symbol using `parseSymbol(tx.symbol, tx.sourceType).base`
   - Record: `{ transactionId, symbol (base), realizedPnlEur: fromDecimal(pnlEur), feeEur: '0', taxYear }`

3. For each `futures_fee`:
   - Fee in EUR = `toDecimal(tx.amount).times(toDecimal(tx.eurPrice))` (fees are negative amounts, so feeEur will be negative — store as positive for clarity using `.abs()`)
   - Record: `{ transactionId, symbol (base), realizedPnlEur: '0', feeEur: fromDecimal(feeEur), taxYear }`

4. For each `futures_funding`:
   - Funding payments can be positive (received) or negative (paid)
   - EUR value = `toDecimal(tx.amount).times(toDecimal(tx.eurPrice))`
   - Record as realized P&L: `{ transactionId, symbol, realizedPnlEur: fromDecimal(eurValue), feeEur: '0', taxYear }`

5. All non-futures canonical types → add to `skipped` array with reason "not a futures transaction".

**Test cases (RED phase):**
- `records realized P&L for futures_close_long`: Close long with positive amount. Assert correct EUR P&L.
- `records realized P&L for futures_close_short`: Close short with positive amount. Assert correct EUR P&L.
- `handles negative P&L (loss)`: Close with negative amount. Assert negative P&L preserved.
- `records futures_fee as positive fee`: Fee transaction with negative amount. Assert feeEur is positive (abs).
- `records futures_funding as P&L`: Funding with positive and negative amounts. Assert both recorded.
- `skips futures_open_long and futures_open_short`: Open transactions. Assert they appear in skipped.
- `skips non-futures transactions`: buy, sell, earn_interest. Assert all skipped.
- `normalizes symbol from futures format`: "BTCUSDT" from futures_tx. Assert symbol is "BTC".
- `processes multiple transactions across different symbols`: BTC and ETH futures. Assert separate records.
  </behavior>
  <implementation>
Export `runFuturesPnlEngine(transactions: EngineTransaction[]): FuturesPnlResult`.

Simple linear pass over transactions. No state accumulation needed — each transaction is independent.

Use `parseSymbol(tx.symbol, tx.sourceType as SourceType).base` for symbol normalization.
All arithmetic via `toDecimal()` / Decimal operations / `fromDecimal()` for output.
  </implementation>
</feature>

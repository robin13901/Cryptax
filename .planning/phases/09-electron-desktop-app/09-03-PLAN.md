1. Create `packages/electron/src/main/db-path.ts`:

```typescript
import { app } from 'electron';
import path from 'node:path';
import fs from 'node:fs';

/**
 * Resolve the SQLite database file path in the user's app data directory.
 * On Windows: %APPDATA%/Cryptax/cryptax.db
 * On macOS: ~/Library/Application Support/Cryptax/cryptax.db
 * On Linux: ~/.config/Cryptax/cryptax.db
 */
export function resolveDbPath(): string {
  const userData = app.getPath('userData');
  return path.join(userData, 'cryptax.db');
}

/**
 * Ensure Drizzle migration files exist in the user data directory.
 * In production (packaged): copies from process.resourcesPath/drizzle (placed by extraResources)
 * In development: points directly to the backend's source drizzle folder
 * Returns the path to the migrations folder.
 */
export function resolveMigrationsPath(): string {
  if (app.isPackaged) {
    // In production: migrations are in resources/drizzle via extraResources in electron-builder.yml
    return path.join(process.resourcesPath, 'drizzle');
  }
  // In development: use the backend's source drizzle folder directly
  // __dirname in bundled output is packages/electron/out/main/
  // Backend drizzle folder is packages/backend/drizzle/
  return path.resolve(__dirname, '../../../backend/drizzle');
}
```

IMPORTANT: `app.getPath('userData')` can only be called after `app.whenReady()` resolves OR after `app.isReady()` returns true. The main `index.ts` must call these functions inside the `whenReady` callback.

IMPORTANT: In dev mode, `__dirname` in electron-vite output points to the compiled output directory (e.g., `packages/electron/out/main/`). The relative path `../../../backend/drizzle` navigates up to the monorepo root and then into the backend drizzle folder. Verify this relative path is correct by counting directory levels.

2. Create `packages/electron/src/main/server.ts`:

```typescript
import { serve } from '@hono/node-server';
import type { ServerType } from '@hono/node-server';

let serverInstance: ServerType | null = null;

/**
 * Start the Hono backend server on the given port.
 * Uses dynamic import to load the backend AFTER environment variables are set.
 * This is critical because db/client.ts reads DB_PATH at module evaluation time.
 */
export async function startBackendServer(port = 3001): Promise<void> {
  // Dynamic import: the backend must not be imported until DB_PATH is set
  const { createApp } = await import('@cryptax/backend/app.js');

  const app = createApp();

  return new Promise<void>((resolve) => {
    serverInstance = serve({ fetch: app.fetch, port }, () => {
      console.log(`[electron] Backend server running on http://localhost:${port}`);
      resolve();
    });
  });
}

/**
 * Stop the embedded backend server gracefully.
 */
export function stopBackendServer(): Promise<void> {
  return new Promise<void>((resolve) => {
    if (serverInstance) {
      serverInstance.close(() => {
        serverInstance = null;
        resolve();
      });
    } else {
      resolve();
    }
  });
}
```

IMPORTANT: The `import('@cryptax/backend/app.js')` is a dynamic import — this is critical. Static imports are hoisted and evaluated before any code runs. Since `db/client.ts` (imported transitively by `app.ts`) reads `process.env.DB_PATH` at evaluation time, we must set `DB_PATH` before the import happens. Dynamic import ensures this ordering.

NOTE on import path: `@cryptax/backend/app.js` uses the workspace package name. For this to resolve, the backend package needs an `exports` field in its `package.json`, or we use a relative path. Check which works:
- Option A: `@cryptax/backend/app.js` (requires package.json exports map)
- Option B: Relative path from the bundled output
- Option C: electron-vite resolve alias in the config

If `@cryptax/backend` workspace resolution doesn't work for subpath imports, fall back to importing the createApp from a path that electron-vite can resolve. You may need to add to the backend's `package.json`:
```json
"exports": {
  ".": "./src/index.ts",
  "./app": "./src/app.ts",
  "./app.js": "./src/app.ts",
  "./db/client": "./src/db/client.ts",
  "./db/client.js": "./src/db/client.ts"
}
```
Or use a resolve alias in `electron.vite.config.ts`.

Alternatively, since `externalizeDepsPlugin()` externalizes workspace deps, the dynamic import will resolve at runtime through Node.js module resolution. In that case `@cryptax/backend/app.js` should work because npm workspace linking puts the package in node_modules.

Also, since the backend uses `"module": "NodeNext"` with `.js` extensions, and electron-vite externalizes it, the `.js` extension in the import path is correct — it resolves to the compiled `.js` file in the backend's dist (or source via tsx).

For the dynamic import to work at all, the backend package needs an exports map OR the file needs to be importable by path. Add to `packages/backend/package.json` an exports field if needed:
```json
"exports": {
  ".": "./src/index.ts",
  "./app": "./src/app.ts",
  "./app.js": "./src/app.js",
  "./db/client": "./src/db/client.ts",
  "./db/client.js": "./src/db/client.js"
}
```

1. Create `packages/electron/src/main/index.ts`:

```typescript
import { app, BrowserWindow } from 'electron';
import path from 'node:path';
import { resolveDbPath, resolveMigrationsPath } from './db-path.js';
import { startBackendServer, stopBackendServer } from './server.js';

let mainWindow: BrowserWindow | null = null;

async function createWindow(): Promise<void> {
  // 1. Resolve database and migration paths BEFORE importing backend
  const dbPath = resolveDbPath();
  const migrationsPath = resolveMigrationsPath();

  // 2. Set environment variables for the backend's db/client.ts
  //    These must be set before the dynamic import in startBackendServer()
  process.env.DB_PATH = dbPath;
  process.env.MIGRATIONS_PATH = migrationsPath;

  // 3. Optionally call initDb explicitly for more control
  //    (The env var approach works too since db/client.ts reads DB_PATH on auto-init)
  //    We use env vars here because the auto-init path in db/client.ts already handles this.

  // 4. Start the embedded Hono backend server
  await startBackendServer(3001);

  // 5. Trigger the tax engine background run after server starts
  //    (Import dynamically to ensure backend is fully loaded)
  try {
    const { triggerEngineBackground } = await import('@cryptax/backend/routes/engine.js');
    triggerEngineBackground();
  } catch {
    // Non-critical — engine will run on first manual trigger
    console.warn('[electron] Background engine trigger skipped');
  }

  // 6. Create the BrowserWindow
  mainWindow = new BrowserWindow({
    width: 1280,
    height: 800,
    minWidth: 900,
    minHeight: 600,
    title: 'Cryptax',
    webPreferences: {
      preload: path.join(__dirname, '../preload/index.js'),
      contextIsolation: true,    // DEFAULT — never disable
      nodeIntegration: false,    // DEFAULT — never enable
      sandbox: true,             // DEFAULT since Electron 20
    },
  });

  // 7. Load the frontend
  //    In dev: electron-vite sets ELECTRON_RENDERER_URL (or VITE_DEV_SERVER_URL)
  //    In prod: load the bundled index.html from out/renderer/
  const devUrl = process.env.ELECTRON_RENDERER_URL;
  if (devUrl) {
    mainWindow.loadURL(devUrl);
  } else {
    mainWindow.loadFile(path.join(__dirname, '../renderer/index.html'));
  }

  // 8. Open DevTools in development
  if (!app.isPackaged) {
    mainWindow.webContents.openDevTools({ mode: 'detach' });
  }

  mainWindow.on('closed', () => {
    mainWindow = null;
  });
}

// App lifecycle
app.whenReady().then(createWindow);

app.on('activate', () => {
  // macOS: re-create window when dock icon is clicked and no windows are open
  if (BrowserWindow.getAllWindows().length === 0) {
    createWindow();
  }
});

app.on('window-all-closed', async () => {
  await stopBackendServer();
  if (process.platform !== 'darwin') {
    app.quit();
  }
});
```

NOTE on env var `ELECTRON_RENDERER_URL`: electron-vite automatically sets this in dev mode. If the actual env var name differs by electron-vite version, check the docs. Common alternatives: `VITE_DEV_SERVER_URL`, `ELECTRON_RENDERER_URL`. Use whichever the installed version provides.

NOTE on `triggerEngineBackground`: This import path `@cryptax/backend/routes/engine.js` needs the same subpath exports treatment as `@cryptax/backend/app.js`. If subpath resolution fails, either:
- Add the path to backend's package.json exports map
- Or skip the background engine trigger in Electron (it's non-critical; the engine runs on manual trigger or on import)

IMPORTANT: The `process.env.DB_PATH = dbPath` line MUST execute before `startBackendServer()` is called, because `startBackendServer` does `await import('@cryptax/backend/app.js')` which transitively imports `db/client.ts` which reads `process.env.DB_PATH`.

IMPORTANT: Do NOT use `process.env.MIGRATIONS_PATH` unless you also update `db/client.ts` to read it. In Plan 01, the `initDb()` function accepts `migrationsPath` as a parameter. If using env vars only, the auto-init path in `db/client.ts` uses `defaultMigrationsPath()` which computes the path relative to the compiled file. This will NOT be correct in Electron packaged mode.

BETTER APPROACH: Instead of relying on env vars for migrations, call `initDb()` explicitly:
```typescript
// Before startBackendServer:
const { initDb } = await import('@cryptax/backend/db/client.js');
initDb({ dbPath, migrationsPath });
// Then start server (createApp won't re-init because initDb was already called)
await startBackendServer(3001);
```

This requires the dynamic import of `initDb` before the server starts. Restructure `createWindow()` to:
1. Resolve paths
2. Dynamic import `initDb` from `@cryptax/backend/db/client.js`
3. Call `initDb({ dbPath, migrationsPath })`
4. Start the backend server
5. Create the BrowserWindow

import { contextBridge } from 'electron';

/**
 * Minimal preload script.

This is intentionally minimal. The frontend uses `fetch('/api/...')` for all communication. No Electron IPC is needed because the Hono backend runs as an HTTP server.

<task type="auto">
  <name>Task 2: Make db/client.ts support deferred initialization with configurable paths</name>
  <files>packages/backend/src/db/client.ts</files>
  <action>
Refactor `packages/backend/src/db/client.ts` to support two modes:

**Mode A (existing behavior — automatic):** When the module is imported without calling `initDb()`, it behaves exactly as today: reads `process.env.DB_PATH ?? 'cryptax.db'`, opens the database, runs migrations. This preserves all existing test behavior (tests mock this module via `vi.mock`).

**Mode B (Electron — explicit):** Calling `initDb({ dbPath, migrationsPath })` before any DB access initializes the database at the specified path and uses the specified migrations folder.

Implementation approach — use a lazy singleton pattern:

```typescript
import { dirname, resolve } from 'node:path';
import { fileURLToPath } from 'node:url';
import type { Database as SqliteDatabase } from 'better-sqlite3';
import Database from 'better-sqlite3';
import { drizzle } from 'drizzle-orm/better-sqlite3';
import type { BetterSQLite3Database } from 'drizzle-orm/better-sqlite3';
import { migrate } from 'drizzle-orm/better-sqlite3/migrator';
import * as schema from './schema.js';

let _db: BetterSQLite3Database<typeof schema> | null = null;
let _sqlite: SqliteDatabase | null = null;

/** Default migrations folder (relative to compiled db/client.js) */
function defaultMigrationsPath(): string {
  const __dirname = dirname(fileURLToPath(import.meta.url));
  return resolve(__dirname, '../../drizzle');
}

/**
 * Initialize the database explicitly with custom paths.
 * Call this BEFORE any code accesses `db` or `sqlite`.
 * Used by the Electron main process to set userData paths.
 */
export function initDb(options: { dbPath: string; migrationsPath?: string }): void {
  if (_db) throw new Error('Database already initialized');
  const sqliteDb = new Database(options.dbPath);
  sqliteDb.pragma('journal_mode = WAL');
  sqliteDb.pragma('foreign_keys = ON');
  _db = drizzle(sqliteDb, { schema });
  _sqlite = sqliteDb;

  if (options.dbPath !== ':memory:') {
    const folder = options.migrationsPath ?? defaultMigrationsPath();
    migrate(_db, { migrationsFolder: folder });
  }
}

/** Auto-initialize on first access (existing behavior). */
function ensureInitialized(): void {
  if (!_db) {
    const dbPath = process.env.DB_PATH ?? 'cryptax.db';
    initDb({ dbPath, migrationsPath: defaultMigrationsPath() });
  }
}

/** Drizzle ORM instance. Auto-initializes on first access. */
export const db: BetterSQLite3Database<typeof schema> = new Proxy({} as BetterSQLite3Database<typeof schema>, {
  get(_target, prop, receiver) {
    ensureInitialized();
    return Reflect.get(_db!, prop, receiver);
  },
});

/** Raw better-sqlite3 instance. Auto-initializes on first access. */
export const sqlite: SqliteDatabase = new Proxy({} as SqliteDatabase, {
  get(_target, prop, receiver) {
    ensureInitialized();
    return Reflect.get(_sqlite!, prop, receiver);
  },
});
```

CRITICAL CONSTRAINTS:
- The `db` and `sqlite` exports MUST remain as named exports at the module level (not functions). Every consumer does `import { db } from '../db/client.js'` and uses `db` directly. A Proxy provides lazy init while keeping the same export shape.
- Tests that `vi.mock('../db/client.js')` completely replace this module — the Proxy code never runs in tests. So this change cannot break any test.
- The `:memory:` check must still skip migrations (both in auto-init path and explicit `initDb` path).
- The `initDb` function is the new API for Electron. It is NOT called by any existing code — only by the future Electron main process.

Also export a `getMigrationsPath()` function that returns the default migrations path — useful for the Electron main process to know where source migrations live for copying:

```typescript
export function getMigrationsPath(): string {
  return defaultMigrationsPath();
}
```

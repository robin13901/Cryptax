```json
    "electron:build": "npm run build -w packages/electron",
    "electron:package": "npm run package -w packages/electron"
  }

```

2. Ensure `packages/backend/package.json` has the `exports` field needed for subpath imports from the Electron main process. Add if not already present (may have been added in Plan 03):
```json
{
  "exports": {
    ".": "./src/index.ts",
    "./app": "./src/app.ts",
    "./app.js": "./src/app.js",
    "./db/client": "./src/db/client.ts",
    "./db/client.js": "./src/db/client.js",
    "./routes/engine": "./src/routes/engine.ts",
    "./routes/engine.js": "./src/routes/engine.js"
  }
}
```

NOTE: The exports field values depend on whether the backend is consumed as source (tsx in dev) or compiled (in prod). For electron-vite dev mode, the externalized imports resolve through Node.js which uses the workspace symlink. Since the backend has `"type": "module"` and compiles to `.js`, the `.js` extension paths should resolve to the compiled output in `dist/`. BUT in dev mode with tsx, the source `.ts` files are what exist. Test both:
- If dynamic `import('@cryptax/backend/app.js')` fails: adjust the exports map
- If it works: leave as-is

3. Attempt to run `npm run electron:dev` and diagnose any startup errors. Common issues to fix:

a) **Import resolution failures**: If `@cryptax/backend/app.js` fails to resolve, check:
   - Does backend need to be built first? (`npm run build -w packages/backend`)
   - Does the exports map need adjusting?
   - Should we use a source-level import with tsx?

b) **electron-vite API differences**: If `externalizeDepsPlugin` is not exported by the installed electron-vite version, replace with manual `external` config:
   ```typescript
   external: ['electron', ...Object.keys(pkg.dependencies || {})]
   ```

c) **Port conflicts**: If port 3001 is already in use (from a running dev server), stop it first.

d) **Native module errors**: If better-sqlite3 throws an ABI mismatch error, run:
   ```bash
   npx electron-rebuild -f -w better-sqlite3
   ```
   Or ensure `electron-builder install-app-deps` runs (it's the postinstall script).

e) **CORS errors in Electron**: If the frontend's fetch calls fail with CORS errors, verify that `createApp()` in `app.ts` uses `cors({ origin: '*' })` instead of `cors()`.

f) **__dirname undefined**: If `__dirname` is undefined in the electron-vite output (ESM mode), use `import.meta.dirname` or compute from `import.meta.url`.

4. Fix each issue iteratively until `npm run electron:dev` successfully:
   - Opens an Electron window
   - Shows the Cryptax frontend (login/setup screen)
   - The embedded backend responds to API calls

5. After dev mode works, verify the existing web dev workflow still works:
   - `npm run dev` (root) should still start backend + frontend as before
   - `npm run test:run` should still pass all tests
